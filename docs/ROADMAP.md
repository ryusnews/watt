# 버전 규칙 · 로드맵

## 버전 `주.부.수` (SemVer)

| 자리 | 언제 올리나 | 올리면 |
|---|---|---|
| **수(패치)** `0.1.N` | 안건(추가 · 수정 · 변경 · 삭제) 하나마다 +1 — 이슈 하나 = 커밋 `Closes #n` = 릴리스 하나 | — |
| **부(마이너)** `0.N.0` | **개수가 아니라 상태로**: 아래 마일스톤의 기준을 통과했을 때, 또는 사용자 쪽 동작이 크게 바뀔 때(설정 · 데이터 형식, 업데이트 방식 등) | 패치는 0 부터 |
| **주(메이저)** `N.0.0` | 0 = 개발 중. **1.0.0** = 일반 사용자에게 자신 있게 권할 수 있을 때 | 부 · 수는 0 부터 |

- 업데이트는 버전을 숫자로 비교한다(0.1.30 < 0.2.0). 사전 릴리스(prerelease)는 업데이트가 건너뛴다.
- 1.0 이후 시험판은 `1.1.0-beta.1` 처럼 GitHub **사전 릴리스**로 낸다(정식판 사용자에게 가지 않음).
- 릴리스 파일은 최근 2개만 둔다(초기 빠른 개발 단계). 지우기 전 내려받기 수는 [downloads.csv](downloads.csv) 에.
- 각 마일스톤은 GitHub 마일스톤과 같다 — 안건은 해당 마일스톤에 넣는다.

## 0.1.x — 빠른 개선 (끝남)
인식 · 번역을 실제 게임 화면으로 모니터링하며 바로바로 고친다. 기능 묶음이 아니라 품질을 잡는 단계.
